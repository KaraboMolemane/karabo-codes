How I Think

Problem‑Solving

Clarify the problem, constrain the scope, and choose the simplest path that works.

  • Define inputs/outputs
  • Break down into steps
  • Prioritize correctness first

Debugging

Reproduce reliably, observe signals, and isolate variables to find root causes.

  • Write a failing test
  • Binary search the code path
  • Instrument with logs/traces

Architecture Decisions

Prefer modular, testable boundaries and incremental complexity only when justified.

  • Small, composable units
  • Explicit contracts
  • Automate the boring parts
